# Progress status board

Read [state-contract](../../reference/state-contract.md), current state, and unseen journal events. Ask the runtime to `reconcile`; canonical state is a validated projection of events, never a handwritten summary.

## Interpretation

Separate activity from demonstrated outcomes. Dispatch establishes ownership; verified evidence establishes acceptance. Keep milestone, parent/child workstream, dependency, risk, and criterion IDs stable across sessions.

Report the runtime result and its evidence:
- **PROGRESSED**: a material accepted change occurred.
- **NO_PROGRESS**: active work has no material accepted change.
- **BLOCKED**: blocking conditions prevent advancement.
- **STALE**: a required input could not be refreshed.
- **TERMINAL**: the work item has a validated final outcome.

The exact precedence is defined in the state contract. Preserve all subordinate facts: a single overall label must never hide progress elsewhere, pending nudges, a stale source, or a blocker.

## Unchanged work

For every unchanged active stream, retain its owner, last verified progress, count of unchanged ticks, known blocker, and next diagnostic action. Keep the nudge key generated by the runtime. Reconciliation retries in one tick must not create duplicate nudges.

The conductor delivers messages and records acknowledgements. Missing delivery stays pending; never claim the team was pinged from a queue entry alone. Terminal or obsolete nudges need explicit disposition, not imaginary delivery.

## Completion

Only close criteria with sourced verified evidence. Do not equate worker handoff `DONE` with acceptance. Parents cannot finish while children or required dependencies remain unresolved. Surface unresolved risks, missing tests, and stale inputs before recommending terminal completion.

Return tick result, actual progress, unchanged streams, pending nudge keys, stale sources, waiting items, and remaining criteria.
